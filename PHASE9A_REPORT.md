# Phase 9A Report — SEO, Analytics, Performance & Accessibility

Stack verified at build time: Laravel 13.43, Filament 5.12, Livewire 4.4.9, Tailwind 4.3.5, PHP 8.3.6.

## What was built

### SEO
- **Layout (`layouts/app.blade.php`)**: per-page meta description with a store-name + tagline fallback, Open Graph (`og:title/description/type/url/locale`, `og:image` when provided) and Twitter card tags on every storefront page.
- **Unique titles/meta per page type**: product (`meta_title`/`meta_description` with short-description fallback), category (`meta_description`), brand, static pages (`meta_title`/`meta_description` from the `pages` table), home (store name + tagline).
- **Canonical URLs**: home, product, category/brand/search listings (canonical to the base listing URL), static pages.
- **JSON-LD** (`app/Support/Seo.php`, built only from storefront-safe fields):
  - `Product` on the product page: name, SKU, brand, images, `offers` with `priceCurrency=EGP`, effective price, `InStock`/`OutOfStock` availability, and `aggregateRating` **only** when approved reviews exist (rating average + count of approved reviews only).
  - `BreadcrumbList` on the product page.
  - `Organization`/`LocalBusiness` on the home page (name, URL, address/email/phone/social only when the owner configured them).
- **Sitemap** (`SitemapController`, `GET /sitemap.xml`): generated dynamically — home, active categories, active brands, active products, active static pages, contact, wholesale. Inactive items excluded; `/_ui`, admin, cart, checkout and account URLs are never included.
- **Robots** (`GET /robots.txt` + matching static `public/robots.txt`): disallows `/admin`, `/cart`, `/checkout`, `/account`, `/login`, `/register`; includes the `Sitemap:` line. Search/filter query URLs are **not** blocked (they are handled with noindex meta, per spec §9).
- **Noindex verified/added**: filtered listings (already), search page (now noindex even without query parameters), cart, checkout, login, register, track-order, all account pages, and the order success page (`noindex,nofollow`).

### Analytics (GA4)
- `app/Support/Analytics.php` is the single payload builder, working from an explicit allowlist (item id/name/brand/category, price, quantity, totals, shipping, transaction id). It never includes `cost_price`, phone, email, address, customer names or payment data — payloads cannot be extended ad hoc by callers.
- The layout emits `<meta name="ga4-id">` **only** when the `ga4_measurement_id` setting is non-empty; `resources/js/analytics.js` is dynamically imported only when that meta exists, loads gtag.js, and sends:
  - `page_view` on initial load and on every `livewire:navigated`;
  - `view_item` (product page, server-rendered payload);
  - `add_to_cart` (browser event dispatched by `ProductPage`/`AddToCartButton` **only after** CartService stored the line server-side);
  - `begin_checkout` (checkout page, server-rendered payload);
  - `purchase` (success page; deduped twice: a per-order session flag in `OrderSuccessController` prevents re-rendering the payload on reload/back, and `analytics.js` dedupes again by `transaction_id` in `sessionStorage`).
- Search Console verification meta is rendered only when `search_console_verification` is set.

### Performance / accessibility pass (code-inspection based; see NOT RUN)
- **Images**: WebP conversions (`thumb` 400 / `medium` 800 / `large` 1200) were already generated by Spatie; this phase wires them into `srcset`/`sizes` on product cards (400/800/1200w) and the product gallery (800/1200w). LCP rules were already in place (first gallery image and first hero slide are `eager` + `fetchpriority="high"`, never animated in; below-fold images lazy with explicit width/height).
- **Alt texts**: product images use the media alt custom property with a product-name fallback; brand logos use the brand name; decorative thumbnails use empty alt. Verified in card/gallery/home templates.
- **ARIA**: icon-only buttons already carry Arabic `aria-label`s (menu, search, account, drawer close, wishlist toggle with `aria-pressed`, hero pause/play). Verified in header, wishlist button and hero templates.
- **Form labels**: checkout (10 labels), login, register, contact and wholesale forms all use explicit `<label>` elements. Verified by template inspection.
- **Focus visibility**: added a global `:focus-visible` rule (2px primary outline + 2px offset, spec §10.5/§10.8) to `resources/css/app.css`; it did not exist globally before this phase.
- Analytics JS is a separate lazy chunk: built `app.js` gzip stays ~6.65 kB and `analytics.js` is only fetched when GA4 is configured.

## Tests — exact results
- `php artisan test --filter=SeoAnalytics` → **11 passed (71 assertions)**. Covers: sitemap contents/exclusions, robots rules, product canonical/meta/JSON-LD, aggregateRating only from approved reviews, home LocalBusiness JSON-LD, noindex on cart/login/register/track-order/search, no GA/verification tags when settings are empty, GA meta + `view_item` payload when configured (and no cost value in the page), allowlist payload test excluding PII/cost values for `view_item` and `purchase`, and purchase-payload-once-per-session on the success page.
- `php artisan test` (full suite) → **183 passed (707 assertions)** (172 baseline + 11 new).
- `vendor/bin/pint` applied to all touched PHP files.
- `npm run build` → success (Vite, ~0.8s).

## NOT RUN
- **Lighthouse: NOT RUN** — no browser is available in this environment; mobile Performance ≥80 / CLS <0.1 targets are therefore unverified. The code-level budgets (lazy analytics chunk, srcset WebP, eager LCP image, explicit dimensions) are in place.
- **Browser-based accessibility QA (keyboard walk-through, screen reader): NOT RUN** — no browser; checks above are template/code inspections plus the automated tests listed.
- **MySQL verification: NOT RUN** — the suite runs on SQLite locally (see Phase 11 report for the pre-launch MySQL re-verification requirement).

## Assumptions
- GA4 `page_view` uses `send_page_view: false` + manual events so `wire:navigate` navigations are counted exactly once.
- `public/robots.txt` (which a web server may serve directly, shadowing the route) carries the same disallow rules; the route additionally emits the absolute `Sitemap:` line.
